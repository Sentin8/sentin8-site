### `POST /v1/produce/batch`

`POST /v1/produce/batch` - produce N events in one call (BUS-3, bus DESIGN §4.3 / README §7). Each row runs through the SAME single-produce core (validation, rate limit, inbox persist, XADD, stamp, audit) - the batch is a transport-level optimization, not a transaction: rows are independent and a failed row does not roll back its siblings.

Gate: `sentin8:bus:produce`

**Request body** (`application/json`):

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `events` | `ProduceRequest`[] | yes | The batched events (max 100 per call - matches the outbox relay drain batch). |

**Responses**:

| Status | Description | Body |
| --- | --- | --- |
| 200 | Batch accepted (per-row results) | `ProduceBatchResponse` |
| 400 | Batch too large (max 100) | - |
| 403 | Missing `bus:produce` scope | - |
| 429 | Per-family produce rate limit | - |
